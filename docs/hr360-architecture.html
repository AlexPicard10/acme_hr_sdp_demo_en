ACME HR 360

From raw extract to a governed 360° view: the extracts of two subsidiaries concatenated, then a declarative bronze → silver → gold pipeline written in SQL and in Python (same logic, two schemas). Synthetic HR data (fictional company ACME), to upskill HR Data teams.

1Bronze · Append Flows

Ingestion and concatenation

Each subsidiary drops its files into its Volume. Auto Loader reads them, and one Append Flow per subsidiary writes into the same table, with source_entity. A 3rd subsidiary = one more flow, no full refresh.

bronze_employees
bronze_absences
2Silver · Expectations

Employee quality & enrichment

Typing, derived columns (age_bracket, seniority), join to the departments reference. Expectations drop or flag non-compliant rows.

silver_employees
3Silver · Window functions

Deduplicated latest delivery

In the latest file of each subsidiary, ROW_NUMBER() keeps the most recent version of each employee; LAG() shows what the correction changed. A Materialized View: windows are not supported in streaming.

silver_employees_last_extract
4Silver · Expectations

Absence quality

Consistent dates, plausible duration, known type. The free-text note (comment) is kept, empty strings become NULL.

silver_absences
5Gold · Auto CDC · SCD 1

Current state per employee

Auto CDC in SCD Type 1: one up-to-date row per employee, incrementally. The STRUCT(extract_ts, updated_at) sequence breaks ties between duplicates of the same file.

gold_employees_current
6Gold · Auto CDC · SCD 2

Mobility history

SCD Type 2 with TRACK HISTORY ON department, contract and job title (__START_AT / __END_AT).

gold_employees_history
7Gold · Materialized View

360° employee view

A Materialized View combines the current state with the year-to-date absence KPIs; the result is stored and refreshed on every pipeline update.

gold_employee_360
8Unity Catalog

Governed consumption

AI/BI dashboards, Genie, apps or notebooks read the gold tables: access, lineage and audit governed by Unity Catalog.
